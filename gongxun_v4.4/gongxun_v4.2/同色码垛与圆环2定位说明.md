# 同色码垛与圆环2定位

## 扫码分工

| 组别 | 变量 | 现在的用途 |
| --- | --- | --- |
| 第1组 | A1/B1/C1 | 第一圈槽1/2/3的取料颜色，1~6 |
| 第2组 | A2/B2/C2 | 第一圈加工、暂存的目标圆环，1~3 |
| 第3组 | A3/B3/C3 | 第二圈槽1/2/3的取料颜色，必须和第1组为同一组三种颜色，允许换序 |
| 第4组 | A4/B4/C4 | 第二圈加工的放置/取回圆环，不再决定第二圈暂存目标 |

扫码完成后 `StorageStack_Configure()` 保存第1/2/3组的快照，与 `mat_1/2/3` 无关。
第一层布局直接计算为：

```c
ring_color[A2] = A1;
ring_color[B2] = B1;
ring_color[C2] = C1;
```

这里 `ring_color[1..3]` 下标就是圆环号，0号下标不用。配置时得到的是计划布局；第一圈定位和放置流程成功返回、`first_layer_done=1` 后，才允许按该布局码第二层。
每组必须合法且不重复，两圈颜色集合必须相同。配置失败时保持扫码工位停车，查看 `g_storage_stack.fault`，不会继续抓放。

## 第一圈暂存

主任务 `MainTask_RunStageAction()` 的 `case 3` 调用 `StorageStack_RunFirst()`：

```text
Maixcam_setmode(2) 识别地面圆环
→ 原收臂/摄像头准备动作，等待700ms
→ VisualPosition_Run(155,138,0°,1像素,8000ms)
→ 定位返回OK才关闭底盘查询并调用原Storage_First
→ 按第2组目标圆环放第一层
→ 恢复原查询开关、收回机构
→ first_layer_done=1，放行路径
```

定位失败会停车、收臂并锁存故障，不执行放置、不标记第一层完成。

## 第二圈圆环2物料定位与码垛

主任务 `case 6` 调用 `StorageStack_RunSecond()`。定位仍使用原来的组合和参数：

```c
modeX = ColorToCameraMode(g_storage_stack.ring_color[2]);
Maixcam_setmode(modeX);
/* 沿用原准备动作和700ms等待 */
VisualPosition_Run(78U, 93U, 0.0f, 1U, 8000U);
```

使用的是圆环2上的第一圈物料颜色，不是 `B2` 位置号，也不一定是 `B1`。
摄像头颜色模式为：红3、绿4、蓝5、黑6、黄7、浅蓝8。发送帧统一为三字节 `FF 模式 FE`；模式8已修正为发3字节，避免越界多读第4个字节。

保留原 `VisualPosition_Run()` 控制器：检查坐标帧是否超过300ms未更新，并要求3个不同的有效帧位于位置容差内。定位过程中保持指定0°航向并让出CPU，自动管理底盘查询开关。
只有返回 `VISUAL_POSITION_OK`，才调用原来的第二层机构动作。
无帧、坐标未到位、单帧重复读取等造成定位超时时，不码垛；故障锁存后不会在主任务循环中重复尝试动作。排除原因后复位重新启动。

三个码垛目标这样计算：槽1的第二圈颜色A3去第一层同色圆环，槽2的B3、槽3的C3同理。机构仍可按槽1→2→3操作，但目标圆环不再固定，也不依赖第4组加工顺序。

例如扫码 `642 + 312 + 264 + 123`：

| 圆环 | 第一层颜色 |
| --- | --- |
| 1 | 绿4 |
| 2 | 黄2 |
| 3 | 浅蓝6 |

第二圈槽1/2/3颜色为黄2、浅蓝6、绿4，码垛目标为环2、环3、环1。定位选黄物料模式7；第二圈加工仍使用第4组的环1、环2、环3。

## Watch

直接加入 `g_storage_stack`：

- `configured`：1=扫码快照及同色目标通过校验。
- `ring_color[2]`：圆环2的第一层颜色。
- `camera_mode`：第二圈物料定位模式3~8。
- `target_ring[0..2]`：第二圈槽1/2/3的码垛目标圆环。
- `first_layer_done`：第一圈放置流程已返回，允许进入第二圈码垛。
- `second_layer_done`：第二层流程已返回，允许继续路径。
- `position_attempted`、`position_result`：是否做过定位及最近完成的定位结果；不要把上一圈的OK当作本圈已经完成，要结合完成标志/当前路径阶段判断。
- `fault`：正常为 `STORAGE_STACK_FAULT_NONE`。BAD_SCAN表示扫码非法或两圈颜色集合不一致；NO_FIRST_LAYER表示还未放好第一层；FIRST/SECOND_POSITION表示对应定位失败。

路径在故障时保持 `PATH_FOLLOWER_WAIT_ACTION`。故障没有自动重试，避免反复抓放。
完成标志表示动作函数已执行返回，不是传感器确认物料确实抓住/放下。

## 保持不变与验证范围

同色码垛接入时保持原抓取逻辑及机构参数。之后原料抓取触发已改为颜色+坐标窗口判断，不再使用额外400/3200ms等待，详见《原料抓取坐标窗口说明》。两圈加工顺序、机械脉冲/舵机/第二层高度、底盘和路径配置、车辆定位坐标及航向不改。
软件测试使用生产代码和模拟数据，覆盖4320种颜色/圆环/抓取顺序组合、扫码校验、主任务两次暂存与第二次加工、定位失败禁止放置、重复调用不重复放料、六色模式和三字节发送。
原视觉控制器及底层机构动作已与改动前备份比较，保持不变。

该工程没有摄像头端识别程序，软件测试不能验证实际颜色阈值或(78,93)是否是实车正确抓放基准。摄像头模式3~8需要仍回传现有10字节坐标协议；代码没有摄像头模式切换应答校验，仍需实车确认模式确实生效、坐标更新及定位偏差。
没有烧录或驱动实车。
