# 原料抓取：颜色和坐标窗口

三件物料现在统一按同一条件触发，不再区分第1件/第2、3件的固定等待时间。
两圈取料仍共用 `GrabMaterialsInOrder()`，抓取顺序、车上槽位和同色码垛规则不变。

## 触发条件

必须同时满足：

- 在开始等当前物料之后，收到一个新的视觉帧，不能使用上一次机构动作期间的旧帧直接抓下一件。
- 数据未过期，默认视觉更新时间距当前不超过300ms。
- `WuLiaoData` 等于当前要抓的颜色编号。
- X和Y分别进入目标坐标的可调容差内。

按用户确认的默认值，目标为 `(60,100)`、容差为±5像素，即X在55~65、Y在95~105，边界也算到位。X和Y都满足才允许抓。
这些是摄像头画面坐标，不是地图上的毫米坐标。

匹配后直接调用原 `grab_middle(槽号)`，没有额外400/3200ms等待。未匹配时只 `osDelay(5)` 让出CPU继续等下一次检查，这不是固定抓取延时。
读取颜色/坐标前后会比较帧计数；如果中途新帧更新导致取样不一致，就丢弃该样本重新读。

抓取函数内部的升降、舵机、夹爪动作和等待时间没有修改。坐标到位指的是启动整套原抓取动作，不代表夹爪在判断通过的同一时刻已经闭合；实际抓取点仍需结合机构动作时间校准。

## 参数在哪里调整

`bsp/inc/action.h`：

```c
#define RAW_MATERIAL_GRAB_TARGET_X_PX       60U
#define RAW_MATERIAL_GRAB_TARGET_Y_PX      100U
#define RAW_MATERIAL_GRAB_TOLERANCE_PX       5U
#define RAW_MATERIAL_GRAB_FRAME_TIMEOUT_MS 300U
#define RAW_MATERIAL_GRAB_POLL_MS            5U
```

主要调整前三个参数。容差0表示必须完全匹配坐标，调大容差会扩大抓取窗口。
改参数后重新编译、烧录，不要通过修改调试快照调整控制参数。
这些参数只管“何时开始抓”，不改变原料区车辆视觉定位的 `(60,100,-90°,1像素,8000ms)`，也不改变码垛区车辆定位参数。

旧 `RAW_MATERIAL_NEXT_GRAB_DELAY_MS=3200U` 仅保留兼容/备查，已经没有参与抓取触发，改它不会改变当前抓取窗口。

## Watch

展开 `g_raw_grab`：

| 字段 | 含义 |
| --- | --- |
| status | WAITING=等待匹配，EXECUTING=已触发原机构动作，DONE=三件流程已返回 |
| slot / target_color | 当前抓到哪个槽、当前目标颜色编号 |
| measured_color | 最近一次一致读取的视觉颜色 |
| target_x_px / target_y_px / tolerance_px | 本次默认抓取窗口参数快照 |
| measured_x_px / measured_y_px | 最近读取的物料坐标 |
| error_x_px / error_y_px | 实测坐标减目标坐标，默认两者均需在-5~+5内 |
| frame_count / frame_age_ms | 最近读取的帧号和取样时的数据年龄 |
| fresh | 当前物料等待之后的新帧且未过期才为1 |
| ready | 1表示已触发/正在执行当前物料的机构动作，三件完成后清为0 |

这些值是处理时的快照：机构动作执行期间不会持续刷新 `g_raw_grab`。实时相机数据仍可直接看 `YuanData[0]`、`YuanData[1]`、`WuLiaoData` 和 `maixcam_frame_count`。

等待中不动时，依次检查是否有新帧、颜色是否正确、X/Y误差是否超窗；新帧不更新或物料一直未到窗口时，函数会继续等待，不会超时后强行抓取。

## 软件验证

电脑测试使用实际生产抓取函数，模拟视觉帧和机构动作，不访问硬件。
覆盖三件同规则、颜色与XY同时匹配、边界包含、坐标越界、错误颜色、旧帧/零帧/过期帧、时钟与帧号回绕、目标/容差可调、槽位记录及重复调用。
同色码垛回归测试继续通过。旧延时测试入口已转到新的坐标窗口测试，历史C测试保留但不再编译。
实际颜色识别、窗口基准和夹爪闭合时机仍需要实车验证，没有烧录或驱动实车。
