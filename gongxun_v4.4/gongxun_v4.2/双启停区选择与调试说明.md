# 双启停区选择与调试说明

## 现在怎么启动

Keil工程入口为本目录的 `MDK-ARM/gongxun_v4.uvprojx`，目标仍为 `gongxun_v4`。

| 按键 | 选择区域 | 放车中心/最终回库中心 | 初始车头朝向 |
| --- | --- | --- | --- |
| PD12 | 1号启停区 | (150,150) mm | `PP_START_YAW_DEG`，默认向下/Y+/0° |
| PD13 | 2号启停区 | (150,2250) mm | `PP_START_YAW_DEG`，默认向下/Y+/0° |

两键为上拉输入、按下低电平，20ms确认后锁定。两个键同时按下不选择，松开一个再选择即可。
启动后不再读按键；换区需要复位、重新放车、重新选择。保持全场右上角原点，X+向左、Y+向下，不镜像地图或工位。

当前雷达开关仍为 `APP_RADAR_ENABLED=0`：先选区，再按固定地图规划无新增障碍的最优路线。
以后接上雷达，将 `Core/Inc/app_config.h` 中开关改为1：同一个按键选择也会传给雷达的选区接口。
上电机构归位仍按原程序执行；未按路径启动键不代表机构不会运动。

## 改初始摆车朝向：只改一个宏

修改 `bsp/inc/path_plan.h`：

```c
#define PP_START_YAW_DEG 0 // 单位度，必须填整数；默认保持现在的摆车朝向。
```

从上方看，相对目前车头朝地图Y+的摆法：填 `90` 表示逆时针旋转90°，填 `-90` 表示顺时针旋转90°，`180`/`-180` 表示反向。只允许0、90、-90、180、-180，其他配置会编译报错，防止任意斜放在300×300启停区内导致车身越界。

两启停区共用这个配置，自动用于初始地图位姿、IMU原始角度到地图角度的零点对齐、保持初始航向离站，以及A*第一段的出发转向代价。不需要改任务函数或IMU驱动，也不要去旋转地图节点。必须把实车摆成与宏一致的朝向，再编译、烧录、复位并按键。

初始转了90°也不会在蓝块内先转回0°：先保持配置角度全向移到现有离站安全点，再调整道路行驶方向。工位对接角度和原有回库流程不变，2号区仍先在安全点转到0°再入库。

该宏描述的是车辆相对固定地图的实际朝向，不是要求IMU上电显示这个数。即使IMU原始读数不为0，启动流程也会自动校准；Watch应看 `g_chassis_runtime.nav.pose.yaw_deg`，起步前应接近宏值（180/-180等价）。原始 `g_chassis_runtime.imu_yaw_deg` 不一定等于宏值。

几何提醒：车体275×300mm，摆成±90°时X方向投影为300mm，蓝块中心摆放在右边线方向也没有名义余量；不能仅凭角度宏保证不压线，需实车核对摆正误差、轮径/里程计误差和机构包络。只验证标称矩形几何，不替代硬件急停和实车低风险测试。

## 总体调用顺序

```text
StartDefaultTask
  → MainTask_PrepareStart
      → PD12/PD13选择启停区
      → path_plan_select_start_zone
      → 等待任务2：四轮有效回读、里程计初始化、IMU有效
      → ChassisRuntime_CorrectPoseWithSequence(选区中心, PP_START_YAW_DEG)
      → 等待实际完成序号匹配，并核验位置/航向
  → 雷达启动并扫描，或RadarStartup_PlanWithoutRadar
  → A*生成8段路径（path.start_zone记录本次选区）
  → PathFollower_Start保存选区配置快照
  → 保持PP_START_YAW_DEG全向离站到安全点
  → 执行路径、工位对接、原工位动作、离站
  → 返回所选启停区
```

`CorrectPoseWithSequence`只修改软件地图坐标和IMU航向零点，不把车移动到指定中心。因此必须把实车放在选区中心，并按 `PP_START_YAW_DEG` 摆正朝向。
它的返回成功只表示入队，主任务已等待任务2真正执行，避免2区仍用1区 `(150,150)` 的旧位姿起步。
等待编码器/IMU最多5秒，等待位姿修正最多1秒；异常时停车并进入 `APP_START_ERROR`，复位后再试，不会超时后强行出发。

## 两区行驶与回库差别

1号区保持原路线：先保持配置的起始航向全向走到 `(300,350)`，再转向沿A*路线前进，最终按原逻辑回到 `(150,150)`。

2号区先保持配置的起始航向全向移入场内到 `(300,2050)`（默认0°时是退入场内），离站限速80rpm，确认真实反馈已进入 `CHASSIS_NAV_TRANSIT_POSITION_MM` 配置的安全点容差范围后才允许第一条道路的转向。本次未调整该容差。

2号区通过原地图右下安全节点2接入A*。没有把节点0搬到右下角，否则原节点0到原料区的道路会穿越黄色禁行区域。
既有9个节点、12条道路、25格障碍编号映射和中间6段任务都不改变。

2号区最后一段按以下顺序执行：

```text
A*最后道路严格到达安全节点2 (275,2060)
  → PATH_FOLLOWER_PARKING_TURN：在安全点严格转到0°
  → PATH_FOLLOWER_PARKING_MOVING：保持0°全向回到(150,2250)，限60rpm
  → WAIT_ACTION（completed_stage=7）
  → 原最后工位处理返回后Continue
  → PATH_FOLLOWER_DONE
```

安全点转正后才全向入库，不在蓝块中心原地自旋。新增入库不增加规划道路点数量。
A*在比较最后一段路线时已计入安全点停车转向代价，统计再加安全点到蓝块中心315mm的曼哈顿距离；不是额外的地图道路。

## Watch看哪些值

| Watch表达式 | 怎么判断 |
| --- | --- |
| `g_app_start.selected_zone` | 未选择为0，PD12后为1，PD13后为2 |
| `g_app_start.status` | WAIT_KEY→WAIT_FEEDBACK→WAIT_POSE→PLANNING→RUNNING→DONE；ERROR是准备/执行失败 |
| `g_app_start.fault` | 正常为NONE；等待失败时区分反馈超时、底盘故障、修正入队失败、修正超时、规划/执行失败 |
| `g_app_start.pose_sequence` | 初始位姿修正序号；准备完成时任务2已经执行过此序号，之后其他命令会更新完成序号 |
| `g_chassis_runtime.nav.pose` | 起步前1区约(150,150,配置角)，2区约(150,2250,配置角)；是融合后的地图位姿，不是原始IMU角度 |
| `g_chassis_runtime.encoder_valid_mask` | 四轮有效应为0x0F |
| `g_chassis_runtime.imu_valid` | 准备出发前应为1 |
| `g_radar_startup.zone` / `g_radar_startup.path.start_zone` | 应与选择区域一致，即使无雷达也记录区号 |
| `g_radar_startup.path_all_valid` | 应为1，表示8段全部规划成功 |
| `g_path_follower.start_zone` | 本次执行锁定的区号 |
| `g_path_follower.status` | 起步START_EXIT_MOVING；2区最后PARKING_TURN→PARKING_MOVING→WAIT_ACTION→DONE |
| `g_path_follower.target_x_mm/target_y_mm/target_yaw_deg` | 当前提交目标；2区入库最终为150、2250、0 |

主流程故障看 `g_app_start.fault`；路径执行故障同时看 `g_path_follower.fault` 和 `g_chassis_runtime.fault/nav.fault`。
原来扫码/工位动作的注释和任务顺序校验没有重新开启或删掉，仍按你当前代码处理；这次只改选区、位姿准备、规划入口和2区回库。

## 参数在哪改

- `bsp/inc/path_plan.h`：初始摆车只改 `PP_START_YAW_DEG`；1区离站 `PP_START_EXIT_*`；2区初始中心 `PP_ZONE2_INITIAL_*`、离站 `PP_ZONE2_EXIT_*`、回库中心 `PP_ZONE2_PARK_*`。三个起始/离站角度宏均为派生值，不要分别修改。
- `bsp/scr/path_plan.c` 的 `start_profiles`：1区初始/回库中心和各区接入节点；改地图节点前要同步检查道路、扫掠范围和雷达映射。
- `bsp/scr/path_follower.c`：起步离站速度 `PATH_START_EXIT_MAX_RPM=80`；2区最终入库 `PATH_PARK_MAX_RPM=60`；工位离站 `PATH_EXIT_MAX_RPM=60`。
- `Core/Src/freertos.c`：启动键去抖、准备阶段反馈和位姿修正超时。

## 正中心停车的边界提醒

按你的要求，2号区最终仍停正中心 `(150,2250)`，没有改成2245。
当前车体X方向275mm、Y方向300mm，在准确0°时车尾刚好到Y=2400，下边界余量为0mm。
即使软件最终容差严格，约1°航向误差会多伸出约2.38mm；向下2mm定位误差也会压线。
因此安全点转正能避免库内大角度自旋，但不能保证零余量停车在实车误差下不压线。首次请低风险验证朝向、实际车体包络和最终停车位置。
